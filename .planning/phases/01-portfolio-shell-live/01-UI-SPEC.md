# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Greenfield note:** This is a brand-new repo — no `package.json`, no `components.json`, no `src/` exist yet (confirmed by directory scan). This contract defines the *target* tokens the executor applies when scaffolding (`create-next-app` → `shadcn init` → `globals.css` `@theme` block), not a retrofit of existing code.

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (locked — `.claude/CLAUDE.md` and `01-RESEARCH.md` Standard Stack both specify `shadcn` CLI 4.13.0) |
| Preset | Custom — no stock `ui.shadcn.com/create` preset. Dark-mode-first OKLCH tokens are defined in the Color section below; apply them via `npx shadcn@latest init` (choose a neutral base, then overwrite `globals.css`'s `@theme` block with the tokens in this spec) during Phase 1 scaffolding |
| Component library | Radix UI (shadcn/ui's default primitive layer as of CLI 4.x) |
| Icon library | `lucide-react` (locked — Standard Stack) |
| Font | Geist Sans (body/headings) + Geist Mono (tech-tags, nav labels) — Next.js 16's default scaffold font pairing via `next/font/google`, zero added dependency. Geist Mono is the phase's "subtle web3 flavor" signature (SITE-02): used only on tech-tag chips, nav labels, and the availability lines — never on headline/body prose |

**Motion (Claude's Discretion per CONTEXT.md):** CSS-only for this phase — Tailwind `transition`/`animate-*` utilities for hover states and a restrained `IntersectionObserver`-triggered fade-up (~12px translate, 250ms ease-out, respects `prefers-reduced-motion`) on section entry. Do **not** install the `motion` package in Phase 1: it adds client JS with no payoff at this phase's zero-interactivity content (works against SITE-03's Lighthouse ≥90 mobile target). Revisit `motion` only when a later phase (e.g. Phase 3 wallet-state transitions) has an actual gesture/sequencing need CSS can't cover.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, tech-tag internal padding |
| sm | 8px | Compact element spacing (tag row gaps, nav link gaps) |
| md | 16px | Default element spacing (card internal padding, paragraph gaps) |
| lg | 24px | Section-internal padding (card padding on mobile, header height) |
| xl | 32px | Layout gaps (gap between project cards) |
| 2xl | 48px | Major section breaks (mobile section-to-section spacing) |
| 3xl | 64px | Page-level spacing (desktop section-to-section spacing, hero top padding) |

Exceptions: header's icon-only GitHub link and any mobile nav toggle use a **44px minimum tap target** (accessibility floor for touch, per WCAG 2.5.5) even though the visible icon is 20-24px — pad the hit area, don't enlarge the icon itself.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | 400 (regular), Geist Mono | 1.5 |
| Body | 16px | 400 (regular), Geist Sans | 1.5 |
| Heading | 28px | 600 (semibold), Geist Sans | 1.2 |
| Display | 48px | 600 (semibold), Geist Sans | 1.2 |

Only two weights used across the whole phase: 400 and 600 — do not introduce 500 or 700.

Usage notes:
- **Display (48px)** — hero headline only (D-05/IDENT-01). On mobile, scale down via `clamp()` or a `text-3xl md:text-5xl`-style responsive step so the full headline still clears above the fold on a 375px viewport — do not shrink below ~32px.
- **Heading (28px)** — section titles ("Projects", "About", "Skills", "Get in touch").
- **Body (16px)** — hero subhead, project blurbs, about copy, availability lines.
- **Label (14px, Geist Mono)** — nav links, tech-tag chips on project cards, skill-group labels, footer links. This is the one place Geist Mono appears — it's the phase's restrained "web3 flavor" cue (SITE-02), not decoration elsewhere.

## Color

Tailwind v4 `@theme` tokens, OKLCH-native (values given as `oklch()` for direct use, with an approximate hex for quick visual reference).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `oklch(0.16 0.01 260)` (~`#121218`) | Page background — a very slightly cool-tinted near-black, not pure neutral gray (the "professional foundation, subtle web3 flavor" cue lives partly here) |
| Secondary (30%) | `oklch(0.22 0.012 260)` (~`#1c1c24`) | Header/nav background, project card surfaces, footer background |
| Accent (10%) | `oklch(0.62 0.19 293)` (~`#8b5cf6`, "Signal Violet") | Reserved for: primary CTA button fill ("View work"), active-section nav-link indicator, project-card left accent stripe, link hover/focus color, focus rings |
| Destructive | `oklch(0.58 0.245 27)` (~`#dc2626`) | Locked now, **not used in Phase 1 UI** (no forms/destructive actions this phase) — reserved so Phase 3's wallet error states reuse this token instead of introducing a new color and breaking the ≤3-accent-color budget (SITE-02) |

Additional neutral (not counted against the accent-color budget — these are surface/text neutrals, not accents):
- Primary text/foreground: `oklch(0.96 0.002 260)` (~`#f4f4f6`) — headings, hero headline
- Muted text: `oklch(0.65 0.01 260)` (~`#9a9aa5`) — body copy, project blurbs, subhead

Accent reserved for: primary CTA button, active nav-link indicator, project-card accent stripe, link hover/focus states, focus rings. **Never** apply Signal Violet as a general link color, background fill, or icon tint outside this list — that's how ≤3-accent-color discipline (SITE-02) erodes.

Total non-neutral colors in play: 2 (Signal Violet accent + Destructive red, reserved/unused this phase) — within the ≤3 cap with one color held in reserve for later phases.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Hero headline (D-05) | Leads with name + role + MetaMask hook — framing locked: "Daniel Cross — Senior React Native / Web3 Engineer, ex-MetaMask, now building on Solana." Exact wording at executor discretion within this framing. |
| Hero subhead (D-07) | "Shipped features to a 30M+ user wallet at MetaMask; now lead engineer on a Solana prediction market." — concrete numbers, no rephrasing needed. |
| Primary CTA (D-08) | "View work" → smooth-scrolls to `#projects` |
| Secondary CTA (D-08) | "Get in touch" → smooth-scrolls to `#contact` |
| Project card links (D-11) | Verb + noun per link, best-available per project, no forced uniformity — e.g. "Live app", "View source", "App Store". Never a bare "Link" or "Click here". |
| Availability line 1 (D-13) | "Contract — via The App Forge AB (outside IR35, UK/EU remote)" |
| Availability line 2 (D-13) | "Full-time — open to senior/staff crypto roles." |
| Email affordance (D-15) | Visible text `hello@danielcross.dev` as both the click target and its own label; on click, label swaps to "Copied!" for 2s, then reverts. The `mailto:hello@danielcross.dev` link is always present alongside it, never replaced. |
| Empty state | N/A this phase — all content is static, typed data (`src/content/*.ts`); there is no data-fetch failure path to design for. If a specific project lacks a link type (e.g. no public source repo), that link button is simply omitted — never rendered as a disabled/placeholder button. |
| Error state | N/A for page content (nothing fetches at runtime). The one client-side interaction (copy-to-clipboard) fails silently and safely: if `navigator.clipboard.writeText()` throws or is unavailable, no error toast is shown — the always-visible `mailto:` link is the fallback path per D-15's "zero friction" requirement. |
| Destructive confirmation | N/A — Phase 1 has no destructive actions (no forms, no auth, no data mutation). The `Destructive` color token above is locked for reuse in Phase 3, not exercised here. |
